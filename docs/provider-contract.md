# Provider contract

Providers are adapters, not agents. They implement the typed protocols in `trade_research.providers`, accept a validated `InstrumentId`, and return immutable fundamental observations or price points. A provider cannot choose analysts, change requests, write reports, issue trades, expose arbitrary queries, or interpret source text as instructions.

Every observation includes the requested instrument identity, a normalized provider kind, an aware observation timestamp, optional bounded vendor field, and safe provenance reference. Provider registries validate runtime protocol conformance and immediately reject wrong-instrument, malformed, non-finite, naive-timestamp, non-closed, or oversized returns. Price histories are capped at 4,096 points, fundamental sources at 1,024 rows, filing metadata at 64 rows, HTTP responses at 4 MiB, and local source files at 16 MiB. CSV and Parquet inputs are checked before materialization; fixed SQL reads include a hard `LIMIT`.

Remote price responses carry canonical SHA-256 snapshot and row references. Derived recursive indicators carry a closed algorithm/window, point count, start/end timestamps, and complete canonical series hash. Exact inputs are included only when the complete relevant input fits the provenance cap; older rows are never retained while newer calculation inputs are silently omitted.

Network credentials remain in the adapter's deployment boundary. Do not place credentials, account identifiers, client addresses, query text, raw positions, raw SEC submissions, or sensitive paths in provenance, exceptions, logs, reports, or persisted requests. SEC is normalized to bounded filing metadata and opaque hashes. Connectivity diagnostics should be read-only, non-billable, and omit secret-bearing URLs; otherwise report `not_attempted`.
